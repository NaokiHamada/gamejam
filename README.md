# 言ったもん雀

4人が自由に発言し、AI審判がその発言をルールに変える、ブラウザ麻雀の試作です。Cloudflare Workers＋Durable Objectsで、離れた場所の4人が遊べます。ルールの解釈にOpenAI APIを使います。

## Cloudflare版の起動と公開

Node.js 22以上を使います。CloudflareのWorkers FreeとSQLite版Durable Objectsで動作する構成です。無料枠のリクエスト数・CPU時間・保存容量などの上限を超えると利用できなくなります。OpenAI APIの利用料金は別途かかります。

```sh
git clone https://github.com/naokihamada/gamejam.git
cd gamejam
npm ci
```

`apikey.local` または環境変数 `OPENAI_API_KEY` にキーを設定します。ローカル起動：

```sh
npm run dev
```

`http://127.0.0.1:8787` を開いてください。開発用スクリプトは既存のキーをWranglerの子プロセスに渡します。別のキー入りファイルを作成せず、キーをコマンド引数や画面にも表示しません。ローカルの対局データとキーを含まない開発用設定は、無視対象の `.wrangler/` に保存されます。本番のSecrets Storeには接続せず、ローカルのキーを使います。キーがなくても、AIによる変更以外は検証できます。

初回のみCloudflareへログインし、公開：

```sh
npx wrangler login
npm run deploy
```

公開版は **Cloudflare Secrets Store** に保存された `OPENAI_API_KEY` を、`OPENAI_KEY_STORE` バインディングの `get()` で実行時に取得します。Worker個別の環境変数Secretとは別の機能です。`apikey.local` はアップロードせず、既存のストアのキーも上書きしません。

別アカウントへ公開する場合は、CloudflareダッシュボードでSecrets Storeへ `OPENAI_API_KEY` を登録し、Workersスコープを有効にしてください。そのストアIDを `wrangler.jsonc` の `secrets_store_secrets[].store_id` に設定します。ストアIDとキー名は設定情報で、キーの値はGitに含めません。

完了時に表示される `https://...workers.dev` のURLを開きます。スマートフォンも同じURLで参加でき、同じWi-Fiである必要はありません。独自ドメインやDockerは不要です。Wranglerの認証で公開できるため、MCPの認証は必須ではありません。

## 遊び方

1. 名前を入れて「新しい卓をつくる」。
2. 友達に招待URLか部屋コードを共有する。1人で遊ぶ場合や人数が足りない場合は、部屋主が「NPCを追加」で空席を埋める。
3. 人間の参加者が「準備完了」（NPCは準備済み）、部屋主が「4人で開局する」。
4. 自分の番に牌を選んで「打牌」。ツモは自動です。あがれるとツモ／ロンのボタンが現れます。
5. チャットで自由に発言。AIの判定でルールが変わり、全員へ同時に届きます。

同じPCならブラウザの4つの**別タブ**でも確認できます。「タブを複製」は参加情報も複製する場合があるので、新しいタブからURLを開いてください。参加情報はタブごとに保存し、再読み込みで復帰できます。

## NPCと遊ぶ

開局前に部屋主が「NPCを追加」を押すと1席ずつ、最大3人のNPCが着席します。「NPCを外す」で友達のために席を空けられます。開局後の追加・削除・人間との交代はできません。次局もNPCと持ち点を引き継ぎ、部屋主が開始します。

NPCは約1.2秒後に自動操作します。あがれる場合はツモ・ロンを優先し、鳴けるときは大明槓・ポン・チーの順で申請します。それ以外は対子・刻子・順子を残す簡易評価で打牌します。あがりの判断は人間と同じ生成コードの判定にも従います。生成コードの効果を打牌評価で特別扱いしません。ただし `discard_check` で禁止された牌は捨てません。生成コードの効果を先読みする戦略や、自動発言・ルール提案はありません。NPCの操作でOpenAI APIを呼び出すことはなく、AI判定中はNPCも停止します。他人の手牌や山は打牌の評価に使いません。

操作予定時刻もSQLiteへ保存し、既存のDurable Objectsアラームで進行します。ブラウザの再読み込みや切断、サーバーの休止・再作成でも進行を再開できます。最後の人間が開局前に退席した場合はNPCも退席し、部屋を削除します。

## Cloudflare版の構成

- **Workers + Static Assets**：画面とHTTPの入口。HTTPSに対応し、配信するのは `public/` の4ファイルのみ。
- **MahjongRoom Durable Object**：1部屋につき1オブジェクト。手牌・山・得点・現在のルールをSQLiteへ保存し、スリープ／インスタンス再作成後に復元します。
- **WebSocket Hibernation**：操作時だけ各プレイヤー専用の状態を通知。定期的なHTTPポーリングをせず、待機時に休止できます。認証トークンをURLへ埋め込みません。
- **Alarms**：アクセスがなくても時間切れの打牌、ロンの締切、AI判定中断後の復旧を処理。最後の対局操作から6時間で部屋を削除します。
- **UsageLimits Durable Object**：全体のAI判定を初期設定で1日100回までに制限。部屋の作り直しでも回避できません。日次の上限は日本時間9:00にリセットします。部屋作成も全体1日100部屋・接続元ごと1分5部屋までです。

`wrangler.jsonc` の `DAILY_AI_LIMIT` でAIの全体上限を変更できます（1〜1000）。失敗したAPI呼び出しも回数に含め、1部屋あたりの80回制限も併用します。合言葉や生成コードの発言効果も、安全性をAIで判定した後に発動します。ルール改変の履歴は直近30件を表示します。

APIキーやプレイヤーのトークン、手牌をログへ出す処理はありません。Cloudflareの実行ログ／トレースはサンプリングを有効にしています。招待コードを知る人が参加する試作で、一般ユーザー向けのアカウント管理はありません。

## APIキー

ローカル開発では、プロジェクト直下の `apikey.local` にキーのみを1行で置くか、`OPENAI_API_KEY=...` 形式で記述してください。環境変数 `OPENAI_API_KEY` があれば優先します。キーはブラウザには送らず、HTTPでのファイル配信対象にも含めません。`apikey.local` は `.gitignore` に登録済みです。

Cloudflare公開版のキーはSecrets Storeで管理します。ローカルファイルの内容はデプロイに含めません。

デフォルトのモデルは [`gpt-6-luna`](https://developers.openai.com/api/docs/models/gpt-6-luna) です。Responses APIとStructured Outputsを使い、推論量は `medium` に設定します。出力上限は推論トークンを含めて8192トークンです。推論に出力枠を使い切った未完了の応答は適用せず、ルールと得点を維持して再開します。

`OPENAI_MODEL` で別のモデルを指定できます。`gpt-6-luna` およびそのスナップショット以外には推論設定を送らず、従来の出力上限2400トークンを使います。モデルの変更に伴う待ち時間・判定の質は実APIで確認してください。APIキーは既存の `OPENAI_API_KEY` をそのまま利用します。`/api/health` とホーム画面で現在のモデルを確認できます。

ローカルの実API検証スクリプトも既定でGPT-6 Lunaを使い、`OPENAI_MODEL` の指定を反映します。基本設定・生成コード・チョンボ・否定の会話・未対応の提案を検証し、各判定の待ち時間を記録します。

発言と現在のルールだけをOpenAIへ送信します。名前、手牌、山牌、他人の発言履歴は送りません。APIは利用料金がかかります。1部屋のAI判定は最大80回、発言は4秒間隔です。Cloudflare版は全体の日次上限も適用します。判定中は対局と時計が停止します。判定中の発言は審議キューに積み、1つずつ順番に判定します。キューは1人2件・部屋全体6件までで、待ち分もAI判定の上限に数えます。局が終わると未判定の待ち分は破棄します。通信・生成エラー時はルールと得点を維持し対局を再開します。チョンボの発言では既存の発言効果も発動しません。

実装は [OpenAI Structured Outputsの公式仕様](https://developers.openai.com/api/docs/guides/structured-outputs) に沿って、Responses APIからJSONを取得します。固定設定に加え、専用のルール言語で生成したコードを検証してサーバーで実行します。JavaScriptのevalやFunctionは使いません。

## 発言の例

面白い提案は基本的に採用します。全員が等しく有利になるルールは、代償やデメリットがなくてもそのまま採用します。1人だけが有利になるルール（親だけ、合言葉を言った人だけ、など）は有利を相殺する代償が必要ですが、ない・足りない場合も却下せず、AI審判が判断して代償や条件を追加したうえで採用し、追加した内容をチャットに表示します。自分で理由づけ・条件・代償を添えて提案すれば、その内容でバランスを取ります。例えば：

- 「対子1組でもあがれることにしよう」「白をジョーカーにしよう」→ 全員が等しく有利なので代償なしで採用。
- 「字牌を捨てたらお供えとして各員へ300点を払う代わりに、追加で1枚ツモれるルールにしよう」
- 「親は毎回2枚ツモれる」→ 審判が「追加ツモした親は各員へ300点払う」などを添えて採用。
- 「今から逆回り！」や「持ち時間を20秒に」のような軽微な調整は、代償なしで採用します。

採否と追加する代償はAIの判断で、例文も採用を保証しません。他のゲームのルールの流用（例：大富豪の7渡しを参考に、7を切ったら手牌を1枚次の人に渡す）、面白い設定や筋の通る理屈もバランスの根拠になり、必ず点数を払う必要はありません。「全員が使える」ルールでも、発動した1人だけが得をするなら代償の対象です。繰返し利用や既存ルールとの組合せ、採用時の即時効果も考慮して代償の大きさを決めます。代償を撤回する提案も、必要なら別の代償を添えて再評価します。

不採用になるのは、代償を調整しても面白くならない提案（意味がない、今のルールとほぼ同じなど）だけです。その場合も減点せず、面白くするヒントを返して再提案を促します。提案された条件・代償を実装できない場合は、利益だけを採用せず実装できる別の代償に置き換えます。採用した条件・代償は効果と同じルールコードへ含めます。判定JSONの `justification` は `not_needed` / `sufficient` / `cost_added`（審判が代償を追加して採用） / `not_fun` で、`not_fun` の採用や `cost_added` の不採用といった矛盾する出力はサーバーでも拒否します。

ルールは全員に等しく適用され、次の局にも持ち越します。部屋主は局の合間に初期化できます。あがり条件・七対子・ジョーカー・あがり点・順番・持ち時間は専用の固定設定を持たず、他の提案と同じ生成コードで変更します。固定設定として残るのは牌種ボーナスと合言葉での得点・即あがりです。

固定設定で表せない提案は、条件式・計算・カウンタを組み合わせたコードを生成して適用します。例えば「字牌が5枚以上ならあがれる」「白を捨てたら500点ずつもらって逆回り」「3回発言するごとに各員から300点」「あがり手の数の合計×100点を追加」などです。通常の会話はルールを変えず、実現できない提案は理由を説明して不採用にします。安全だが未対応というだけでは減点しません。

## チョンボの判定

AIは発言の意図・内容と程度を判定します。対象の提案は、ルール変更・生成コード・既存の合言葉効果を一切実行せず、提案者から他の3人へ均等に支払います。持ち点総計は維持します。

| 内容 | 軽度 | 重大 | 極めて重大 |
| --- | ---: | ---: | ---: |
| 悪意ある処理（秘密の取得、外部送信、攻撃、審判の乗っ取りなど） | 6000 | 12000 | 18000 |
| 過大なサーバー負荷（無限ループ、大量通信、巨大な保存など） | 3000 | 6000 | 9000 |
| トークン浪費（長大な出力、AIを延々呼び出すなど） | 1500 | 3000 | 4500 |
| ゲームをつまらなくする提案（永久に行動禁止、同じ人しか勝てないなど） | 1500 | 3000 | 4500 |

減点額はカテゴリと程度からサーバーが計算し、理由・減点額をチャットと判定履歴に表示します。強いルール、即あがり、逆転、奇妙なルールであること自体は違反ではありません。全員にチャンスや駆け引きがある無茶は積極的に採用し、1人だけが得をする場合は審判が代償を添える方針です。普通の雑談や、違反についての質問・否定・撤回は処罰しないよう指示しています。面白さや意図の判定はAIに依存するため、誤判定の可能性があります。

通信障害・出力不完了・生成コードの形式不正は減点しません。実行中の計算エラー・実行量超過では、そのコードの効果と変数更新を取り消し、該当コードを停止して対局を続行します。

## 生成コードの仕組みと制限

AI審判はルールを**JavaScript**で書きます。Cloudflare Workersでは `eval()` と `new Function()` が使えないため、純JavaScript製のインタプリタ [Sval](https://github.com/Siubaak/sval) でサーバー上で実行します。関数・ループ・再帰・配列メソッド・`Math`・`JSON` などの標準機能を自由に使えるので、捨て牌の回文判定、一つ跳びの順子を認める独自のあがり形、乱数のシャッフル、特定の相手への支払い、次局への状態の持ち越しなども表現できます。「いまのルール」で説明・コード・停止状態を確認できます。

仲間内で遊ぶ前提の設計です。サンドボックスは暴走を止めるためのもので、悪意あるコードからの防御は保証しません。グローバルに `fetch` などはありませんが、セキュリティ境界としては扱っていません。危険な提案は従来どおりAI審判がチョンボとして実行前に止めます。

コードは `on(イベント名, (g, e) => { ... })` でフックを登録します。

```js
// 親は追加で1枚ツモれるが、下家へ1000点払う
on('after_draw', (g, e) => {
  if (e.actor === g.dealer && g.wall.length) { g.pay(e.actor, g.next(e.actor), 1000); g.draw(e.actor); }
});
// 字牌は捨てられない
on('discard_check', (g, e) => isHonor(e.tile) ? '字牌は捨てられません' : true);
// 振り込んだ人は次局のあがり点が倍
on('round_end', (g, e) => { g.memory.double = e.drawn ? -1 : e.loser; });
on('win_score', (g, e) => e.winner === g.memory.double ? e.points * 2 : e.points);
```

| イベント | タイミング・効果 |
| --- | --- |
| `before_round_start` / `after_round_start` | 開局前後。各席1回ずつ（`e.actor`が各席） |
| `before_deal` / `after_deal` | 各人の13枚配牌の前後 |
| `before_draw` / `after_draw` | ツモ前後。後は `e.tile` がツモ牌 |
| `before_discard` / `after_discard` | 打牌前後。`e.tile` は打牌する牌 |
| `before_call` / `after_call` | 鳴き確定時の副露前後。`e.callType`（chi/pon/kan）、`e.source`（放銃席）、`e.tiles` |
| `before_turn` / `after_turn` | 手番交代の前後。`e.actor` は次の手番 |
| `before_speech` / `after_speech` | 安全判定を通過した発言の前後。`e.text` |
| `before_score` / `win_score` / `after_score` | あがり点計算。`e.points` を受け取り、数値を返すと置き換え |
| `payment` | 支払い直前。`e.deltas`（席ごとの増減）を書き換えるか返すと支払いを変更（責任払いなど） |
| `round_end` / `after_round_end` | 局の終了後（あがり・流局）。`e.winner`・`e.loser`・`e.deltas`・`e.drawn` |
| `win_check` | あがれるかの照会。`e.allowed`（通常判定）を受け取り、true/falseを返すと置き換え |
| `discard_check` | 打牌できるかの照会。falseか理由の文字列を返すと禁止。全牌禁止の手番は制限なし。時間切れ・NPCは許可された牌を選ぶ |
| `call_check` | 鳴けるかの照会。falseを返すとその鳴きを表示・受付しない |

`draw` などの短縮名は `after_draw` などと同じです。照会イベントは状態を変えず、ボタン表示のため頻繁に呼ばれます。

`g` は卓の作業用コピーで、書き換えると処理後に検証して一括反映します。`g.players[席]` の `hand`・`river`・`melds`・`score`、`g.wall`（先頭が次のツモ）、`g.direction`（1/−1）、`g.turnSeconds`（5〜300秒に丸め）を直接変更できます。`g.turn`・`g.dealer`・`g.round`・`g.claim` も参照できます。補助関数は `g.draw(席, 枚数)`、`g.pay(払う席, 受け取る席, 点)`、`g.award(席, 点)`（他3人から各点）、`g.win(席, 名前)`（即あがり。開局・配牌・得点計算・支払い・局の終了・照会では無効）、`g.say(文字列)`（卓へのお知らせ）、`g.random(n)`、`g.shuffle(配列)`、`g.next(席)` です。共通ヘルパーとして `TILES`・`rank`・`suit`・`isHonor`・`isTerminal`・`sortTiles`・`countTile`・`isWinningHand(牌, {melds, joker, shape})` があります。

`g.memory` はコードごとの永続オブジェクトで、局をまたいで保存されます（JSONで8000文字まで）。役・翻・ドラ・役満のような組込みの仕組みはないので、審判は `win_score` での加点などに読み替えます。暗槓やリーチのように操作ボタンがない宣言は、「カン」「リーチ」などの発言を `after_speech` で受けて表現します。

新規・置換コードは直近2ステップ分（最大4個のツモ・打牌・鳴き・手番交代の前後イベント）にも順に適用します。通常操作や既存コードは重複実行しません。採用したその場から有効で、提案した発言自体にも適用します。

失敗時の扱い：

- コードごとに変更を検証し、例外・実行量超過・不正な牌（34種以外）・上限超過があれば、そのイベントでのそのコードの変更（牌・点数・記録）だけを取り消して停止します。減点はありません。
- ループ1周・関数1呼び出しを1ステップと数え、1回のフック実行は20万ステップまでです。無限ループや無限再帰もここで止まります。
- Svalの制約で、プロパティへの分割代入（`[a.x, b.x] = [b.x, a.x]`）は実行時エラーになります。変数への分割代入は使えます。
- 1コード6000文字、同時8コード・合計24000文字。1か所の牌は200枚、卓全体1024枚まで。配牌中は後続席の13枚ずつを山に残します。
- ツモ・ロンには14−副露数×3枚の手牌が必要です（`g.win` は除く）。ロン・鳴き待ち中に牌を動かすと待ちを解除して次の手番へ進みます。
- あがり点は100点単位、0〜1000000点です。
- AIは発言ごとに1回、GPT-6 Lunaは推論を含め出力最大12000トークン（その他のモデルは4000）、入力は32000文字、応答本体は256KiB以内です（APIが指示文を返送するため）。失敗時は「出力が長すぎて途中で終了」「時間切れ」「生成コードを実行できませんでした（理由）」など原因を表示します。
- AIへ送るのは発言、固定設定、生成コード・ID・タイトル・停止状態だけです。手牌、点数、名前、認証情報、`g.memory` の値は送りません。
- 旧形式（JSON命令列）の生成ルールは、復元時に停止中として残ります。

## 麻雀部分の範囲

- 初期136枚、13枚配牌（生成ルールのコピー・削除で総数が変わる場合があります）。ツモ後に1枚捨てます。副露なしはツモ後14枚、副露が1組増えるごとに手元の枚数は3枚減ります（槓の4枚は副露側で保持）。
- 初期のあがり条件は4面子＋1雀頭／七対子。役は不要。初期状態ではジョーカーはありません。生成コードで指定した牌を代用牌として判定できます。
- ツモ、打牌、ロン、チー、ポン、大明槓、流局、次局、得点移動に対応。チーは進行方向の次席のみ。ポン・チー後はツモせず打牌し、大明槓後は山から1枚補充ツモします。副露は全員に公開し、あがり判定で固定した面子として扱います。
- 暗槓・加槓、嶺上牌専用の山・槓ドラ、リーチ、ドラ、フリテン、国士無双、親の連荘、半荘進行は未実装。席風は表示用です。
- 初期持ち時間45秒、時間切れでツモ切り。ロン・鳴きは8秒以内。同時ロンは最初にサーバーで受け付けた1人。鳴きは申請を保存し、全候補の応答完了または締切で確定します。ロンが最優先、ポン・大明槓はチーより優先、同順位は進行方向の近い席を優先します。鳴き申請はその打牌へのロンを放棄します。「見送る」でロン・鳴きをともに辞退し、待ちを短縮できます。
- 初期6000点。ロンは放銃者払い、ツモ・合言葉あがりは他3人払い（1人100点単位に切り上げ）。牌種ボーナスと生成コード補正を含む基本点は0〜1000000点。合言葉ボーナスは他3人から指定点ずつ。すべて持ち点総計を保存し、負の点数でも続行します。
- 他人の手牌・参加トークンは配信しません。あがり手牌のみ終了時に公開します。
- 接続が切れても席を保持し、自動ツモ切りで進行します。同じタブで再読み込みして復帰してください。
- 音声認識はありません。発言はテキストチャットです。

Cloudflare版はHTTPSで公開でき、ルーターのポート開放は不要です。
