# 言ったもん雀

4人が自由に発言し、AI審判がその発言をルールに変える、ブラウザ麻雀の試作です。Cloudflare Workers＋Durable Objectsで、離れた場所の4人が遊べます。ルールの解釈にOpenAI APIを使います。

## Cloudflare版の起動と公開

Node.js 22以上を使います。CloudflareのWorkers FreeとSQLite版Durable Objectsで動作する構成です。無料枠のリクエスト数・CPU時間・保存容量などの上限を超えると利用できなくなります。OpenAI APIの利用料金は別途かかります。

```sh
git clone https://github.com/naokihamada/gamejam.git
cd gamejam
npm ci
```

`apikey.local` または環境変数 `OPENAI_API_KEY` にキーを設定します。ローカル起動：

```sh
npm run dev
```

`http://127.0.0.1:8787` を開いてください。開発用スクリプトは既存のキーをWranglerの子プロセスに渡します。別のキー入りファイルを作成せず、キーをコマンド引数や画面にも表示しません。ローカルの対局データとキーを含まない開発用設定は、無視対象の `.wrangler/` に保存されます。本番のSecrets Storeには接続せず、ローカルのキーを使います。キーがなくても、AIによる変更以外は検証できます。

初回のみCloudflareへログインし、公開：

```sh
npx wrangler login
npm run deploy
```

公開版は **Cloudflare Secrets Store** に保存された `OPENAI_API_KEY` を、`OPENAI_KEY_STORE` バインディングの `get()` で実行時に取得します。Worker個別の環境変数Secretとは別の機能です。`apikey.local` はアップロードせず、既存のストアのキーも上書きしません。

別アカウントへ公開する場合は、CloudflareダッシュボードでSecrets Storeへ `OPENAI_API_KEY` を登録し、Workersスコープを有効にしてください。そのストアIDを `wrangler.jsonc` の `secrets_store_secrets[].store_id` に設定します。ストアIDとキー名は設定情報で、キーの値はGitに含めません。

完了時に表示される `https://...workers.dev` のURLを開きます。スマートフォンも同じURLで参加でき、同じWi-Fiである必要はありません。独自ドメインやDockerは不要です。Wranglerの認証で公開できるため、MCPの認証は必須ではありません。

## 遊び方

1. 名前を入れて「新しい卓をつくる」。
2. 友達に招待URLか部屋コードを共有する。1人で遊ぶ場合や人数が足りない場合は、部屋主が「NPCを追加」で空席を埋める。
3. 人間の参加者が「準備完了」（NPCは準備済み）、部屋主が「4人で開局する」。
4. 自分の番に牌を選んで「打牌」。ツモは自動です。あがれるとツモ／ロンのボタンが現れます。
5. チャットで自由に発言。AIの判定でルールが変わり、全員へ同時に届きます。

同じPCならブラウザの4つの**別タブ**でも確認できます。「タブを複製」は参加情報も複製する場合があるので、新しいタブからURLを開いてください。参加情報はタブごとに保存し、再読み込みで復帰できます。

## NPCと遊ぶ

開局前に部屋主が「NPCを追加」を押すと1席ずつ、最大3人のNPCが着席します。「NPCを外す」で友達のために席を空けられます。開局後の追加・削除・人間との交代はできません。次局もNPCと持ち点を引き継ぎ、部屋主が開始します。

NPCは約1.2秒後に自動操作します。あがれる場合はツモ・ロンを優先し、鳴けるときは大明槓・ポン・チーの順で申請します。それ以外は対子・刻子・順子を残す簡易評価で打牌します。あがりの判断は人間と同じ生成コードの判定にも従います。生成コードの効果を打牌評価で特別扱いしません。専用言語の任意の効果を先読みする戦略や、自動発言・ルール提案はありません。NPCの操作でOpenAI APIを呼び出すことはなく、AI判定中はNPCも停止します。他人の手牌や山は打牌の評価に使いません。

操作予定時刻もSQLiteへ保存し、既存のDurable Objectsアラームで進行します。ブラウザの再読み込みや切断、サーバーの休止・再作成でも進行を再開できます。最後の人間が開局前に退席した場合はNPCも退席し、部屋を削除します。

## Cloudflare版の構成

- **Workers + Static Assets**：画面とHTTPの入口。HTTPSに対応し、配信するのは `public/` の4ファイルのみ。
- **MahjongRoom Durable Object**：1部屋につき1オブジェクト。手牌・山・得点・現在のルールをSQLiteへ保存し、スリープ／インスタンス再作成後に復元します。
- **WebSocket Hibernation**：操作時だけ各プレイヤー専用の状態を通知。定期的なHTTPポーリングをせず、待機時に休止できます。認証トークンをURLへ埋め込みません。
- **Alarms**：アクセスがなくても時間切れの打牌、ロンの締切、AI判定中断後の復旧を処理。最後の対局操作から6時間で部屋を削除します。
- **UsageLimits Durable Object**：全体のAI判定を初期設定で1日100回までに制限。部屋の作り直しでも回避できません。日次の上限は日本時間9:00にリセットします。部屋作成も全体1日100部屋・接続元ごと1分5部屋までです。

`wrangler.jsonc` の `DAILY_AI_LIMIT` でAIの全体上限を変更できます（1〜1000）。失敗したAPI呼び出しも回数に含め、1部屋あたりの80回制限も併用します。合言葉や生成コードの発言効果も、安全性をAIで判定した後に発動します。ルール改変の履歴は直近30件を表示します。

APIキーやプレイヤーのトークン、手牌をログへ出す処理はありません。Cloudflareの実行ログ／トレースはサンプリングを有効にしています。招待コードを知る人が参加する試作で、一般ユーザー向けのアカウント管理はありません。

## APIキー

ローカル開発では、プロジェクト直下の `apikey.local` にキーのみを1行で置くか、`OPENAI_API_KEY=...` 形式で記述してください。環境変数 `OPENAI_API_KEY` があれば優先します。キーはブラウザには送らず、HTTPでのファイル配信対象にも含めません。`apikey.local` は `.gitignore` に登録済みです。

Cloudflare公開版のキーはSecrets Storeで管理します。ローカルファイルの内容はデプロイに含めません。

デフォルトのモデルは [`gpt-6-luna`](https://developers.openai.com/api/docs/models/gpt-6-luna) です。Responses APIとStructured Outputsを使い、推論量は `medium` に設定します。出力上限は推論トークンを含めて8192トークンです。推論に出力枠を使い切った未完了の応答は適用せず、ルールと得点を維持して再開します。

`OPENAI_MODEL` で別のモデルを指定できます。`gpt-6-luna` およびそのスナップショット以外には推論設定を送らず、従来の出力上限2400トークンを使います。モデルの変更に伴う待ち時間・判定の質は実APIで確認してください。APIキーは既存の `OPENAI_API_KEY` をそのまま利用します。`/api/health` とホーム画面で現在のモデルを確認できます。

ローカルの実API検証スクリプトも既定でGPT-6 Lunaを使い、`OPENAI_MODEL` の指定を反映します。基本設定・生成コード・チョンボ・否定の会話・未対応の提案を検証し、各判定の待ち時間を記録します。

発言と現在のルールだけをOpenAIへ送信します。名前、手牌、山牌、他人の発言履歴は送りません。APIは利用料金がかかります。1部屋のAI判定は最大80回、発言は4秒間隔です。Cloudflare版は全体の日次上限も適用します。判定中は対局と時計が停止します。通信・生成エラー時はルールと得点を維持し対局を再開します。チョンボの発言では既存の発言効果も発動しません。

実装は [OpenAI Structured Outputsの公式仕様](https://developers.openai.com/api/docs/guides/structured-outputs) に沿って、Responses APIからJSONを取得します。固定設定に加え、専用のルール言語で生成したコードを検証してサーバーで実行します。JavaScriptのevalやFunctionは使いません。

## 発言の例

- 「白はオールマイティにしよう」→ 白がジョーカーに。
- 「対子が1組あればあがれることにしよう」→ 副露なしなら手が14枚のとき対子1組であがり可能。
- 「今から逆回り！」→ 次のツモから逆回り。
- 「あがったら12000点」→ あがり基本点を12000点に。
- 「索子1枚につき1000点ボーナス」→ あがり手牌の索子に加点。
- 「持ち時間を20秒に」→ 打牌の持ち時間を変更。
- 「『ポテト』と言ったら全員から500点ずつもらえる」→ 設定の**次の発言**から合言葉で得点。
- 「『宇宙』と発言したら即あがり」→ 設定の次の発言から、合言葉を含む発言であがり。

ルールは全員に等しく適用され、次の局にも持ち越します。部屋主は局の合間に初期化できます。あがり条件・七対子・ジョーカー・あがり点・順番・持ち時間は専用の固定設定を持たず、他の提案と同じ生成コードで変更します。固定設定として残るのは牌種ボーナスと合言葉での得点・即あがりです。

固定設定で表せない提案は、条件式・計算・カウンタを組み合わせたコードを生成して適用します。例えば「字牌が5枚以上ならあがれる」「白を捨てたら500点ずつもらって逆回り」「3回発言するごとに各員から300点」「あがり手の数の合計×100点を追加」などです。通常の会話はルールを変えず、実現できない提案は理由を説明して不採用にします。安全だが未対応というだけでは減点しません。

## チョンボの判定

AIは発言の意図・内容と程度を判定します。対象の提案は、ルール変更・生成コード・既存の合言葉効果を一切実行せず、提案者から他の3人へ均等に支払います。持ち点総計は維持します。

| 内容 | 軽度 | 重大 | 極めて重大 |
| --- | ---: | ---: | ---: |
| 悪意ある処理（秘密の取得、外部送信、攻撃、審判の乗っ取りなど） | 6000 | 12000 | 18000 |
| 過大なサーバー負荷（無限ループ、大量通信、巨大な保存など） | 3000 | 6000 | 9000 |
| トークン浪費（長大な出力、AIを延々呼び出すなど） | 1500 | 3000 | 4500 |
| ゲームをつまらなくする提案（永久に行動禁止、同じ人しか勝てないなど） | 1500 | 3000 | 4500 |

減点額はカテゴリと程度からサーバーが計算し、理由・減点額をチャットと判定履歴に表示します。強いルール、即あがり、逆転、奇妙なルールであること自体は違反ではありません。全員にチャンスや駆け引きがある、盛り上がる無茶は積極採用する方針です。普通の雑談や、違反についての質問・否定・撤回は処罰しないよう指示しています。面白さや意図の判定はAIに依存するため、誤判定の可能性があります。

通信障害・出力不完了・生成コードの形式不正は減点しません。実行中の計算エラー・実行量超過では、そのコードの効果と変数更新を取り消し、該当コードを停止して対局を続行します。

## 生成コードの仕組みと制限

ルール専用のJSON命令列を生成・検証・解釈実行します。固定の候補を選ぶだけではなく、式とイベントを組み合わせて新しい条件や効果をプログラムできます。「いまのルール」で説明・コード・停止状態を確認できます。採用した提案の発言では新コードは発動せず、次のイベントから有効です。

| イベント | タイミング・効果 |
| --- | --- |
| `before_round_start` / `after_round_start` | 開局前後。各席1回。前は手牌・河・副露を空にして山136枚を用意した直後、後は全員の配牌完了後・親のツモ前 |
| `before_deal` / `after_deal` | 各人の13枚配牌の前後。actorは配牌される本人 |
| `before_draw` / `after_draw` | ツモ前後。前は対象牌が未確定でtileは空。後は対象牌を参照でき、即あがりも可能 |
| `before_discard` / `after_discard` | 打牌前後。どちらもtileは打牌する牌。後は手牌から河へ移動済み |
| `before_call` / `after_call` | 鳴き確定時の副露処理前後。申請時には発火しない。actorは鳴く本人、call_typeはchi/pon/kan、sourceは放銃席 |
| `before_turn` / `after_turn` | 手番交代の前後。actorは次の手番の人、turnはそれぞれ交代前／後の席。交代後に通常ツモ、鳴きではカン時だけ補充ツモ |
| `before_speech` / `after_speech` | 安全判定を通過した発言の合言葉処理前後。判定中・違反時には実行しない。後は即あがりも可能 |
| `before_score` / `after_score` | あがり点計算前後。add_pointsで補正、setでカウンタ更新。前のpointsは初期6000点、後は通常ボーナス・旧win_score・前フック補正を反映して1000〜60000点に制限した値。後フック補正後にも同じ範囲に制限して支払い |
| `draw` / `discard` / `speech` | それぞれafter_draw / after_discard / after_speechの互換名。既存コードもそのまま動く |
| `win_check` | あがり条件の追加・置換。`win`は追加、`allow_win`は置換。副作用なし。手元の牌が14−副露数×3枚必要 |
| `win_score` | 既存のあがり基本点補正。before_scoreの後、after_scoreの前に実行 |

`["copies", collection, 牌の式]` で同じ牌の枚数を取得できます。走査中でも利用でき、対子1組なら `["some","hand",[">=",["copies","hand",["get","tile"]],2]]` と表現できます。

式では算術・比較・論理・条件分岐・文字列包含・牌の種類と数・本人の手牌／河と全員の河のcount/sum/every/someを利用できます。公開の点数や局数も参照できます。追加フィールドはmeld_count（副露数）、call_type（鳴き種別、通常は空文字）、source（放銃席、通常は−1）、points（計算中の基本点、通常は0）、loser（得点計算の放銃席、ツモ時は−1）、method（ツモ・ロンなどのあがり名）です。meldsコレクションは本人の副露牌です。handは通常は手元の牌、得点計算時は副露も含む全牌です。各コードはプレイヤーごとに数値変数を最大8個持ち、局をまたいで保存します。既存ルールの撤回・置換も発言で行えます。部屋主による初期化は生成コードとカウンタも消去します。

生成ルールから次の状態も読み取り専用で参照できます（AIへの生成リクエストやブラウザの状態配信に山の内容を追加するものではありません）。

| 参照 | 式 |
| --- | --- |
| 現在の親の席（0〜3、手番・進行方向とは独立） | `["get","dealer"]` |
| 指定席の得点 | `["at","scores",席の式]` |
| 親の得点 | `["at","scores",["get","dealer"]]` |
| 全員の得点合計 | `["sum","scores",["get","tile"]]` |
| 指定席の河にある白の枚数 | `["copies",["river",席の式],"5z"]` |
| 全員の河にある白の枚数 | `["copies","discards","5z"]` |
| 山に残る白の枚数 | `["copies","wall_tiles","5z"]` |
| 次にツモる牌 | `["at","wall_tiles",0]` |

`count/sum/every/some`・`copies`・`at` は `scores`・`wall_tiles`・`["river",席の式]` にも対応します。scoresは席順、河は古い打牌順、wall_tilesは次にツモる順です。scoresの走査中の `get tile` は得点の数値です。`at` の位置は0始まりで、席は0〜3、位置はコレクションの範囲内の整数が必要です。範囲外なら生成コードを停止するため、山の先頭を読む条件には `[">",["get","wall"],0]` を加えてください。これらもイベント開始時のスナップショットを参照します。

牌の移動・コピー・削除は共通の牌プールを指定します。他人の手牌や晒した牌も対象です。

| プール | 内容・順序 |
| --- | --- |
| `"hand"` / `["hand",席の式]` | 本人／指定席の手牌 |
| `"river"` / `["river",席の式]` | 本人／指定席の河、古い打牌順 |
| `"wall_tiles"` | 山、次にツモる順 |
| `"melds"` / `["melds",席の式]` | 本人／指定席の晒した全牌、副露順・各面子の牌順 |
| `["meld",席の式,副露位置の式]` | 指定席の個々のポン・チー・カンや公開グループ（0始まり） |

これらは `size/at/index_of/copies/count/sum/every/some` でも参照できます。`["size",プール]` は枚数、`["index_of",プール,牌の式]` は最初の一致位置（なければ−1）です。他人の手牌の内容はルールの内部で参照できますが、生成AIやブラウザへの状態配信には追加しません。

| 命令 | 効果 |
| --- | --- |
| `["move_tiles",元,先,開始位置,枚数]` | 元の連続範囲を先の末尾へ移動 |
| `["copy_tiles",元,先,開始位置,枚数]` | 元の連続範囲を残し、先の末尾へコピー |
| `["delete_tiles",元,開始位置,枚数]` | 元の連続範囲を削除 |
| `["draw_tiles",枚数]` | 山の先頭から本人の手牌へ追加ツモ |
| `["return_tile",牌]` | 本人の手牌から一致する1枚を山の底へ戻す |
| `["return_hand"]` | 本人の手元の全牌を山の底へ戻す |

席・副露位置・開始位置・枚数・牌には式を指定できます。開始位置は0始まり、枚数は1〜136の整数です。山への追加は最後にツモる側に入ります。元と先が同じプールでも操作できます。`scores` と集約された `discards` は読み取り専用です。全員の河を操作する場合は席別の `river` を使います。

例えば、次の `do` の命令で各操作を表現できます（席は条件や式で選択できます）。

```json
["move_tiles",["hand",1],"hand",0,1]
```

席1の手牌から先頭1枚を本人が取ります。逆に `元="hand", 先=["hand",1]` なら渡します。

```json
["move_tiles",["river",1],"hand",0,1]
["move_tiles",["river",1],"wall_tiles",0,1]
["copy_tiles",["meld",1,0],"hand",0,1]
["delete_tiles",["meld",1,0],0,1]
```

順に、席1の河から1枚取る、河から山へ戻す、最初の副露の1枚をコピーする、同副露の1枚を削除する操作です。

副露全体への追加は新しい「公開牌」グループとなり、個々の副露への追加はそのグループの末尾に入ります。コード内では空になったグループも位置を保持し、成功時に空グループを除去します。副露の面子が崩れている間は通常のあがりを認めず、面子の形を修復すれば再び判定できます。移動は牌の総数を保ち、コピーと削除は総数を増減させます。同じ牌が4枚を超えることも許可します。

牌操作は `after_deal/after_draw/after_call/after_discard/after_speech` と互換名 `draw/discard/speech` で使えます。追加ツモはツモフックを再発火させません。ロン・鳴きの応答待ち中に牌を操作した場合は、古い申請を解除して次の手番へ進みます。空の手牌も許可し、打牌できない手番はサーバーの次のtickでスキップします。通常の打牌は1枚、ツモ・ロンには14−副露数×3枚が必要です。

操作は記述順・コード登録順に反映します。式はイベント開始時のスナップショットを参照するため、操作後の枚数を使うときはカウンタ等で追跡してください。生成命令では1プール136枚・卓全体1024枚を上限とし、配牌後は後続席の13枚ずつを山に確保します。未配牌の席へ渡した牌には、その後で通常の13枚が追加されます。範囲外・上限超過などの失敗では、そのコードの牌操作・加点・カウンタをまとめて取り消して停止します。

「毎回、通常のツモ後にもう1枚ツモる（合計2枚）」：

```json
[{"on":"after_draw","when":[">",["get","wall"],0],"do":[["draw_tiles",1]]}]
```

「『交換』と発言したら全手牌を山へ戻して同じ枚数ツモる」：

```json
[{"on":"speech","when":["==",["get","text"],"交換"],"do":[
  ["return_hand"],["draw_tiles",["get","hand_count"]]
]}]
```

「3回発言するごとに各員から300点」のコード例：

```json
[{"on":"speech","when":true,"do":[
  ["set","n",["+",["var","n"],1]],
  ["award",["if",["==",["%",["var","n"],3],0],300,0]]
]}]
```

「ポンする前の手牌枚数を記録し、ポン後に各員から300点」のコード例：

```json
[{"on":"before_call","when":["==",["get","call_type"],"pon"],"do":[["set","before",["get","hand_count"]]]},
 {"on":"after_call","when":["==",["get","call_type"],"pon"],"do":[["award",300]]}]
```

フックはコード登録順・コード内の記述順で評価します。同一イベントの手牌・点数は開始時のスナップショットで、同コード内のsetは後続命令から読めます。前後は別イベントなので、前の効果と本処理の変更が後から見えます。処理前のwinは禁止し、処理を飛ばしたり再帰的に呼び出す命令はありません。空の山へのツモ試行はbefore_drawの後に流局となり、after_drawは発火しません。合言葉即あがりではその時点で得点計算へ移り、after_speechは発火しません。

コードにAPIキー・認証トークン・外部通信・ファイル・JavaScriptの関数へアクセスする能力はありません。ループ・再帰・走査の入れ子もありません。専用命令以外の牌の生成や、未実装の暗槓・加槓・リーチなどは生成できません。チー・ポン・大明槓は画面の操作で行い、その前後の効果を生成コードで登録できます。実現できる任意性はこの専用言語の範囲です。

- 1コード3000文字、160式ノード、深さ12、1イベント4096評価ステップ、最大16フック・各8命令。
- 同時8コード・合計12000文字（AIへ渡すJSON表現は15000文字以内）。上限時は既存ルールの撤回が必要です。
- `["allow_win", 真偽式]` は `win_check` 専用で、初期のあがり判定を置き換えます。複数コードは登録順に適用し、後の `allow_win` は前の判定を上書きします。`win` はその位置であがりを許可します。14−副露数×3枚の枚数条件は共通です。
- `["matches_hand", "default" / "standard" / "seven_pairs", "none" または牌コード]` は手牌の形を判定します。`default` は通常形または七対子、`standard` は4面子＋雀頭、`seven_pairs` は七対子のみ。第3要素は代用牌で、副露がある場合は七対子を認めません。例：七対子を禁止するコードは `[{"on":"win_check","when":true,"do":[["allow_win",["matches_hand","standard","none"]]]}]`。
- あがり点の変更は `before_score` の `add_points` で初期6000点との差を加算します。例：12000点なら `[["add_points",6000]]`。順番は `get direction`（通常1・逆−1）と `reverse`、持ち時間は `get turn_seconds` と `turn_time` で扱います。いずれも生成コードとして一覧表示・置換・撤回できます。イベントが変更した方向・秒数は対局状態として保持し、コード撤回ではその後の発動だけを止めます。部屋主の初期化では方向と秒数も戻します。
- 加減点は1コード1イベントにつき各員から／各員へ最大3000点、あがり点補正は±24000点。100点単位。複数コードの効果は登録順に適用し、条件と公開値はイベント開始時の値を使います。
- AIは発言ごとに1回、GPT-6 Lunaは推論を含め出力最大8192トークン（その他のモデルは2400）、発言と現在ルールの入力は18000文字、応答本体は64KiB以内。自動再試行やコードからのAI呼び出しはありません。従来の4秒間隔・1卓80回・全体日次上限も適用します。
- AIへ送るのは発言、固定設定、生成コード・ID・タイトル・停止状態だけです。手牌、点数、名前、認証情報、コードのカウンタ値は送りません。

## 麻雀部分の範囲

- 初期136枚、13枚配牌（生成ルールのコピー・削除で総数が変わる場合があります）。ツモ後に1枚捨てます。副露なしはツモ後14枚、副露が1組増えるごとに手元の枚数は3枚減ります（槓の4枚は副露側で保持）。
- 初期のあがり条件は4面子＋1雀頭／七対子。役は不要。初期状態ではジョーカーはありません。生成コードで指定した牌を代用牌として判定できます。
- ツモ、打牌、ロン、チー、ポン、大明槓、流局、次局、得点移動に対応。チーは進行方向の次席のみ。ポン・チー後はツモせず打牌し、大明槓後は山から1枚補充ツモします。副露は全員に公開し、あがり判定で固定した面子として扱います。
- 暗槓・加槓、嶺上牌専用の山・槓ドラ、リーチ、ドラ、フリテン、国士無双、親の連荘、半荘進行は未実装。席風は表示用です。
- 初期持ち時間45秒、時間切れでツモ切り。ロン・鳴きは8秒以内。同時ロンは最初にサーバーで受け付けた1人。鳴きは申請を保存し、全候補の応答完了または締切で確定します。ロンが最優先、ポン・大明槓はチーより優先、同順位は進行方向の近い席を優先します。鳴き申請はその打牌へのロンを放棄します。「見送る」でロン・鳴きをともに辞退し、待ちを短縮できます。
- 初期6000点。ロンは放銃者払い、ツモ・合言葉あがりは他3人払い（1人100点単位に切り上げ）。牌種ボーナスと生成コード補正を含む基本点は1000〜60000点。合言葉ボーナスは他3人から指定点ずつ。すべて持ち点総計を保存し、負の点数でも続行します。
- 他人の手牌・参加トークンは配信しません。あがり手牌のみ終了時に公開します。
- 接続が切れても席を保持し、自動ツモ切りで進行します。同じタブで再読み込みして復帰してください。
- 音声認識はありません。発言はテキストチャットです。

Cloudflare版はHTTPSで公開でき、ルーターのポート開放は不要です。
