# 言ったもん雀

4人が自由に発言し、AI審判がその発言をルールに変える、ブラウザ麻雀の試作です。Cloudflare Workers＋Durable Objectsで、離れた場所の4人が遊べます。ルールの解釈にOpenAI APIを使います。元のPython LAN版も含みます。

## Cloudflare版の起動と公開

Node.js 22以上を使います。CloudflareのWorkers FreeとSQLite版Durable Objectsで動作する構成です。無料枠のリクエスト数・CPU時間・保存容量などの上限を超えると利用できなくなります。OpenAI APIの利用料金は別途かかります。

```sh
git clone https://github.com/naokihamada/gamejam.git
cd gamejam
npm ci
```

`apikey.local` または環境変数 `OPENAI_API_KEY` にキーを設定します。ローカル起動：

```sh
npm run dev
```

`http://127.0.0.1:8787` を開いてください。開発用スクリプトは既存のキーをWranglerの子プロセスに渡します。別のキー入りファイルを作成せず、キーをコマンド引数や画面にも表示しません。ローカルの対局データとキーを含まない開発用設定は、無視対象の `.wrangler/` に保存されます。本番のSecrets Storeには接続せず、ローカルのキーを使います。キーがなくても、AIによる変更以外は検証できます。

初回のみCloudflareへログインし、公開：

```sh
npx wrangler login
npm run deploy
```

公開版は **Cloudflare Secrets Store** に保存された `OPENAI_API_KEY` を、`OPENAI_KEY_STORE` バインディングの `get()` で実行時に取得します。Worker個別の環境変数Secretとは別の機能です。`apikey.local` はアップロードせず、既存のストアのキーも上書きしません。

別アカウントへ公開する場合は、CloudflareダッシュボードでSecrets Storeへ `OPENAI_API_KEY` を登録し、Workersスコープを有効にしてください。そのストアIDを `wrangler.jsonc` の `secrets_store_secrets[].store_id` に設定します。ストアIDとキー名は設定情報で、キーの値はGitに含めません。

完了時に表示される `https://...workers.dev` のURLを開きます。スマートフォンも同じURLで参加でき、同じWi-Fiである必要はありません。独自ドメインやDockerは不要です。Wranglerの認証で公開できるため、MCPの認証は必須ではありません。

## 遊び方

1. 名前を入れて「新しい卓をつくる」。
2. 残りの3人に招待URLか部屋コードを共有する。
3. 全員が「準備完了」、部屋主が「4人で開局する」。
4. 自分の番に牌を選んで「打牌」。ツモは自動です。あがれるとツモ／ロンのボタンが現れます。
5. チャットで自由に発言。AIの判定でルールが変わり、全員へ同時に届きます。

同じPCならブラウザの4つの**別タブ**でも確認できます。「タブを複製」は参加情報も複製する場合があるので、新しいタブからURLを開いてください。参加情報はタブごとに保存し、再読み込みで復帰できます。

## Cloudflare版の構成

- **Workers + Static Assets**：画面とHTTPの入口。HTTPSに対応し、配信するのは `public/` の4ファイルのみ。
- **MahjongRoom Durable Object**：1部屋につき1オブジェクト。手牌・山・得点・現在のルールをSQLiteへ保存し、スリープ／インスタンス再作成後に復元します。
- **WebSocket Hibernation**：操作時だけ各プレイヤー専用の状態を通知。定期的なHTTPポーリングをせず、待機時に休止できます。認証トークンをURLへ埋め込みません。
- **Alarms**：アクセスがなくても時間切れの打牌、ロンの締切、AI判定中断後の復旧を処理。最後の対局操作から6時間で部屋を削除します。
- **UsageLimits Durable Object**：全体のAI判定を初期設定で1日100回までに制限。部屋の作り直しでも回避できません。日次の上限は日本時間9:00にリセットします。部屋作成も全体1日100部屋・接続元ごと1分5部屋までです。

`wrangler.jsonc` の `DAILY_AI_LIMIT` でAIの全体上限を変更できます（1〜1000）。失敗したAPI呼び出しも回数に含め、1部屋あたりの80回制限も併用します。合言葉の得点・即あがりはローカル処理なのでAPI呼び出しなしで発動します。ルール改変の履歴は直近30件を表示します。

APIキーやプレイヤーのトークン、手牌をログへ出す処理はありません。Cloudflareの実行ログ／トレースはサンプリングを有効にしています。招待コードを知る人が参加する試作で、一般ユーザー向けのアカウント管理はありません。

## PythonのLAN版

元のPython版も残しています。Python 3.10以上が必要で、追加パッケージは不要です。

```sh
python3 server.py
```

このPCは `http://localhost:8765`、同じWi-Fiの端末は表示されたLAN URLを開きます。Windowsでは `py -3 server.py` を使えます。ポート指定は `--port 8080`。Python版はHTTPポーリングで同期し、対局はメモリ上なのでサーバー終了時に消えます。

## APIキー

ローカル開発／Python版では、プロジェクト直下の `apikey.local` にキーのみを1行で置くか、`OPENAI_API_KEY=...` 形式で記述してください。環境変数 `OPENAI_API_KEY` があれば優先します。キーはブラウザには送らず、HTTPでのファイル配信対象にも含めません。`apikey.local` は `.gitignore` に登録済みです。

Cloudflare公開版のキーはSecrets Storeで管理します。ローカルファイルの内容はデプロイに含めません。

デフォルトのモデルは `gpt-4.1-mini`。必要なら `OPENAI_MODEL` 環境変数でStructured Outputsに対応したモデルに変更できます。

発言と現在のルールだけをOpenAIへ送信します。名前、手牌、山牌、他人の発言履歴は送りません。APIは利用料金がかかります。1部屋のAI判定は最大80回、発言は4秒間隔です。Cloudflare版は全体の日次上限も適用します。Python版のみサーバー全体でAI同時判定は2回までです。判定中は対局と時計が停止します。通信エラー時はルールを維持し対局を再開します。合言葉による得点はAI解釈前のサーバー処理です。

実装は [OpenAI Structured Outputsの公式仕様](https://developers.openai.com/api/docs/guides/structured-outputs) に沿って、Responses APIからJSONを取得します。生成されたプログラムを実行せず、検証した値だけを対局に適用します。

## 発言の例

- 「白はオールマイティにしよう」→ 白がジョーカーに。
- 「対子が1組あればあがれることにしよう」→ 手が14枚のとき対子1組であがり可能。
- 「今から逆回り！」→ 次のツモから逆回り。
- 「あがったら12000点」→ あがり基本点を12000点に。
- 「索子1枚につき1000点ボーナス」→ あがり手牌の索子に加点。
- 「持ち時間を20秒に」→ 打牌の持ち時間を変更。
- 「『ポテト』と言ったら全員から500点ずつもらえる」→ 設定の**次の発言**から合言葉で得点。
- 「『宇宙』と発言したら即あがり」→ 設定の次の発言から、合言葉を含む発言であがり。

ルールは全員に等しく適用され、次の局にも持ち越します。部屋主は局の合間に初期化できます。対応する変更は、あがり条件（通常／対子1組／対子2組／刻子1組／すべて中張牌）、七対子、ジョーカー1種、基本点、牌種ボーナス、順番、持ち時間、合言葉での得点・即あがりです。

自由な文章を入力できますが、任意の仕組みを生成する実装ではありません。AIは対応範囲へ解釈し、できないことは不採用または対応できる範囲を説明します。会話だけならルールを変えません。

## 麻雀部分の範囲

- 136枚、13枚配牌。14枚になったら1枚捨てます。
- 初期のあがり条件は4面子＋1雀頭／七対子。役は不要。ジョーカーは指定牌の代わりになります。
- ツモ、打牌、ロン、流局、次局、得点移動に対応。
- 鳴き（チー・ポン・カン）、リーチ、ドラ、フリテン、国士無双、親の連荘、半荘進行は未実装。席風は表示用です。
- 初期持ち時間45秒、時間切れでツモ切り。ロンは8秒以内、同時ロンは最初にサーバーで受け付けた1人。見送りで待ちを短縮できます。
- 初期6000点。ロンは放銃者払い、ツモ・合言葉あがりは他3人払い（1人100点単位に切り上げ）。牌種ボーナスを含む基本点は最大60000点。合言葉ボーナスは他3人から指定点ずつ。すべて持ち点総計を保存し、負の点数でも続行します。
- 他人の手牌・参加トークンは配信しません。あがり手牌のみ終了時に公開します。
- 接続が切れても席を保持し、自動ツモ切りで進行します。同じタブで再読み込みして復帰してください。
- 音声認識はありません。発言はテキストチャットです。

Cloudflare版はHTTPSで公開でき、ルーターのポート開放は不要です。Python版はLAN内での試遊用です。

## Python LAN版で接続エラーが出る場合

サーバーは起動時に、localhostとこのMacのLANアドレスに対してHTTPの自己診断を行います。接続時に `Bad file descriptor (errno=9)` が出ても、その接続だけを終了し、対局やほかの接続は保持します。HTTP処理に入る前の受信エラーも捕捉し、同じ原因の長い例外ログを繰り返さず対処方法を1回表示します。

既存のサーバーとポートを競合させずに診断だけ行う場合：

```sh
python3 server.py --diagnose
```

空きポートでHTTPサーバーを起動し、診断後に終了します。OpenAI APIは呼びません。両方成功なら終了コード0、失敗・LANアドレス未検出なら1です。LANの自己診断はMac自身からの確認で、Wi-Fi側の端末間通信制限やスマホ実機での接続成功まで保証するものではありません。

- **localhost OK / LAN NG**：ゲーム以外の最小ソケット通信でもこの状態になる場合、OSやネットワークフィルターによる受信制限が候補です。ポートを変えるだけでは直らないことがあります。
- **localhost OK / LAN OK** なのにスマホから開けない：同じWi-Fiか、端末間通信が許可されているか、アクセス先のIPとポートが正しいかを確認してください。
- **スマホで遊べているがエラーだけ出る**：ブラウザが先読みのために開いて取り消した接続など、対局とは別の接続が失敗している可能性があります。更新したサーバーで不要なトレースバックを防ぎます。

macOSでは「システム設定 → プライバシーとセキュリティ → ローカルネットワーク」で起動元アプリの許可を確認してください。ファイアウォールとは別の設定です。ターミナルから起動するコマンドは通常自動許可の対象です（[Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)）。

Ciscoなどのネットワークフィルターを使っている場合は、その設定／管理者に、同じWi-FiからPythonへのTCP受信（使用中の8765番または8766番）が許可されているかを確認してください。アプリ側でセキュリティ製品やOSの許可設定を自動変更する処理はありません。

更新後は、実行中のサーバーを Ctrl+C で終了してから、同じコマンドで起動し直してください。再起動すると卓の情報は消えます。

2026-10-25にCloudflare版を、Chromeの独立した4セッションで検証しました。参加・準備・実際のOpenAI APIによる「対子1組／12000点／逆回り」への変更・ツモあがり・次局・WebSocket切断からの復帰・再読み込み・390px幅の表示を確認しています。古いHTTP応答がAI判定後の状態を上書きしないことも確認しました。
